チーム運用ルール

朝会の進め方（運用ルール）

  • 朝会のファシリテーターは、前回のファシリテーターが今回のファシリテーターを指名します。
  • ファシリテーターは Microsoft Planner の「In Progress」バケットおよび期日が近い「To Do」バケットのタスクについて、戦略推進課 → キャリアデザイン課の順で進捗確認を行います。
  • 進捗確認を受けたタスクの担当者は、当該タスクの状況を「先行」「順調」「遅延」のいずれかで簡潔に回答します。詳細な経緯や背景説明は朝会では行いません。
  • タスク内容について追加の確認やディスカッションが必要な場合は、朝会とは別途、必要に応じてミーティングを設定します。
  • タスクの進捗確認が一通り完了した後、業務連絡や全体共有事項がないかを確認し、ある場合はその場で発言します。

Microsoft Planner 運用ルール

キャリアデザイン課に関するタスクカードの作成は、原則として長門・島倉・野中の3名が行います。 ただし、上記3名から明示的な指示があった場合に限り、他メンバーによるカード作成を可とします。

タスクの期日設定、カードのバケット移動、チェックリストの変更および更新については、 各タスクの担当者が責任をもって実施します。タスクの状態は常に最新のものを保ち、 実際の進捗と Planner 上の状態に乖離が生じないようにします。

バケットの定義

Planner 上の各バケットは、以下の考え方で運用します。 ここでいう「期間」とは、月次など、あらかじめチームで定めた運用単位を指します。

  • Back log は、現時点では着手予定がなく、 今後対応が必要になる可能性はあるものの、期間内に実施する予定がないタスクを置くバケットとします。
  • To Do は、期間中（例：2026年1月）に実施する予定のタスクを置くバケットとします。
  • In Progress は、現在実行中のタスクを置くバケットとします。

期間内完了を前提とした運用

Planner によるタスク管理では、期間内に To Do および In Progress に存在しているタスクを、 期間終了までにすべて Done に移動（タスク完了）させることを目的とします。 未完了のタスクを次の期間へ持ち越す運用は原則として行いません。

期間内に完了できる量を前提としてタスクを管理し、 タスクの積み上がりが常態化しないよう注意します。

継続タスク・割り込みタスクの扱い

継続的なタスクや、1つのタスク内で複数回の対応や期日が発生する場合は、 最終期限をタスクの期限として設定し、途中の工程や個別対応については チェックリストで管理します。

割り込みタスクが発生した場合は、既存タスクとの優先度や期日を相談したうえで追加します。 相談の判断材料を明確にするため、各タスクには開始日と期日を確実に設定します。

期限が未確定であることを理由に、とりあえず月末日を設定するような運用は行いません。 開始日および期日は、実際の作業予定に基づいて設定し、必要に応じて見直します。

タスク量とコミュニケーションについて

無暗にタスクを追加すると、期間中のタスク量が増え続け、 結果としてタスク割り振りのバランスが崩れやすくなります。 新たにタスクを追加する際は、期間内に完了できる見込みがあるか、 既存タスクと両立できるかを前提に判断します。

タスクを依頼する際は、Planner 上で単に Request に追加するだけで完結させず、 対人コミュニケーションを重視します。 依頼の背景、優先度、期待する完了基準を口頭またはチャットで共有し、 担当者の状況も踏まえたうえで合意を取ってからタスク化します。
